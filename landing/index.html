how it works

Hold, speak, confirm. That is it.

  1. 01

    Hold Ctrl+Space and speak

    Say "message Pulkit that I'll be late". While you talk, text streams in 35 partials. Mic starts in 31.5 ms, transcript tails in 149 ms.

  2. 02

    Check the card

    Voicy matches the name with fuzzy and phonetic lookup, so Paul Kit still finds Pulkit. Correct a mangled name once and the alias is learned for next time. The card shows contact and message. Press Return to send, esc to cancel, Cmd+E to edit.

  3. 03

    WhatsApp opens, you stay in control

    A whatsapp://send deep link prefills the chat. If you enabled auto-send, Voicy posts Return only if WhatsApp is focused and the composer holds exactly that text. Otherwise it aborts with a named error and leaves the text unsent.

how the sentence is cut

What happens to your sentence

Voicy cuts the recipient and message body from what you said. Cleanup only removes disfluencies.

message Pulkit that I'll be late, leaving now
verb, dropped recipient, matched against your contacts connector, dropped body, sliced by character offset, never regenerated

The body is copied by character offset. There is no rewrite step.

Find the person while you speak

Dictation puts words in a box. It does not choose the WhatsApp chat. Voicy takes a name from the sentence, matches it to Contacts, and opens that chat.

Three fixes changed nothing

  1. Contextual strings

    Contact names fed to the recognizer as hints. Byte-identical output.

  2. The en_IN locale

    Byte-identical output, and about 1.5× slower.

  3. A custom language model

    Byte-identical again, at 1576 ms worst case.

So names are fixed after recognition instead. Correct one once and it resolves forever.

It stops before a risky send

What you say is what you get

Your exact words, in your own typing style to friends. No AI rewriting, no cleanup, no surprises. Fidelity is the feature.

Ask when names collide

Two Rahuls means a question, not a guess.

Use a WhatsApp deep link

Voicy opens WhatsApp with a whatsapp://send link. It makes no API calls.

Nothing leaves this Mac

Zero network calls. Airplane mode changes nothing.

  • Your voice never leaves this Mac. Transcription runs on device with Apple Speech. No server, no API key.
  • Your messages are never stored. Not in a log, not in a file, not anywhere. The only thing saved is a name mapping, like Pulkit to this contact. Never message content.
  • Your contacts are read into memory to match a name, never uploaded.
  • Your microphone opens only while you hold the key and closes when you let go. No background listening, no screen recording.

Two permissions to start: Microphone and Contacts. Two optional toggles, hold a key to talk and send without pressing Enter, need Input Monitoring and Accessibility. Both off by default.

half done, not wired in

Received voice notes still need language support

Voicy can decode real WhatsApp voice-note files. Transcription is not ready: the sampled files were Hindi and Punjabi, while the current recognizer runs en_US.

Will this get my WhatsApp banned?

Voicy opens WhatsApp with a deep link. It does not use a WhatsApp API.

Does my audio leave my Mac?

No. Speech runs on-device, and Voicy makes zero network calls.

What is not finished?

Voicy decodes real Ogg-Opus voice notes locally, but transcription is blocked on language, the current recognizer runs en_US and is not wired into the UI. Auto-send posts Return only if WhatsApp is focused and the composer holds exactly the expected text, otherwise it aborts with a named error and the text stays unsent. Delivery still needs a person to confirm. The pitch page lists the limits.
